## 1. Objectives & Architectural Specification
Milestone B0 initiates Part B of the KashOS Master Engineering Plan: Kash Kernel 2.0 (seL4-Class Microkernel in Rust). This milestone establishes the mathematical foundations of the capability system adhering strictly to the seL4 Reference Manual (v16.0.0):

1. **Orthogonal Access Rights (`CapRights`)**:
   - Bit 0: `READ` (`0x1`) — authority to observe object state or read frame memory.
   - Bit 1: `WRITE` (`0x2`) — authority to mutate object state or write frame memory.
   - Bit 2: `GRANT` (`0x4`) — authority to transfer capabilities across synchronous IPC endpoints.
   - Bit 3: `GRANT_REPLY` (`0x8`) — authority to send and receive single-use reply capabilities without granting generic capability transfer.
   - Bitmask `ALL = 0b1111` (`0xF`).
   - Algebraic operations: `contains`, `intersect`, `union`, `bitor`, `bitand`.

2. **Complete seL4 Kernel Object Taxonomy (`KernelObjType`)**:
   - `Untyped { size_bits: u8 }`: Raw physical memory allocator slab.
   - `Frame4K`, `Frame2M`, `Frame1G`: Physical addressable frames.
   - `Endpoint`: Synchronous rendezvous IPC rendezvous point.
   - `Notification`: Asynchronous event word / wait-signal channel.
   - `TCB`: Thread Control Block maintaining execution state and scheduling priority.
   - `CNode { size_bits: u8 }`: Guarded radix capability table node.
   - `SchedContext { budget_us: u64, period_us: u64 }`: Mixed-Criticality System (MCS) execution budget.
   - `Reply`: One-shot return capability generated on `seL4_Call`.
   - `PageTable`, `VSpace`: Hardware memory management and address space structures.
   - `ASIDPool`: Address Space Identifier pool allocator.
   - `IrqControl`, `IrqHandler { irq: u8 }`: Hardware interrupt routing tokens.
   - `IoPortControl`, `IoPort { start_port, end_port }`: x86 port I/O isolation.
   - `IoSpace { pci_bdf, domain_id }`: Peripheral DMA containment token (IOMMU domain).
   - `Vcpu`: Hardware virtualization context.

3. **Capability Descriptor (`Cap`) & CDT Slot (`CdtSlot`)**:
   - Unforgeable capability tokens (`Cap`) containing `kind`, `rights`, and 64-bit unforgeable compartment `badge`.
   - Capability Derivation Tree (`CdtSlot`) maintaining double-linked sibling chains and parent references for deterministic recursive revocation.
