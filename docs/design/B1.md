## 1. Objectives & Architectural Specification
Milestone B1 formalizes and expands the seL4 Untyped Memory Model and Watermark Allocator in Kash Kernel 2.0 adhering strictly to the seL4 Reference Manual (v16.0.0, Section 2.4 "Untyped Memory"):

1. **Watermark Allocation Arithmetic & Alignment**:
   - Every Untyped capability tracks a `watermark` offset within its $2^{size\_bits}$ span.
   - For an object of size $S$, alignment is calculated as:
     $$\text{align\_mask} = \max(S, 16) - 1$$
     $$\text{aligned\_wm} = (\text{cur\_wm} + \text{align\_mask}) \ \& \ !\text{align\_mask}$$
   - For batch retyping of $N$ objects of size $S$:
     $$\text{total\_bytes} = N \times S$$
     $$\text{aligned\_wm} + \text{total\_bytes} \le 2^{size\_bits}$$
   - If capacity is exceeded, allocation fails cleanly with `SeL4Error::NotEnoughMemory` without state modification.

2. **Access Rights Invariant**:
   - In seL4, retyping an Untyped object requires `CapRights::WRITE` authority. Retyping without write authority returns `SeL4Error::InsufficientRights`.

3. **Batch Allocation Protocol (`untyped_retype_batch`)**:
   - Allows atomically carving $N \ge 1$ objects of identical type into consecutive destination slots $[dest\_slot, dest\_slot + N)$.
   - Validates that all target slots are empty prior to committing any slot or advancing the watermark.

4. **Hierarchical Sub-Untyped Partitioning**:
   - An Untyped memory region can be partitioned into smaller Untypeds (`KernelObjType::Untyped { size_bits }`).
   - The derived child Untyped inherits the `is_device` attribute and initializes with `watermark = 0`.
   - The child Untyped can be independently delegated to subsystems (e.g. driver domains, sandboxes) to serve as their local memory allocator.

5. **Device Untyped MMIO Containment**:
   - Physical memory designated as device MMIO (`is_device == true`) can strictly only be retyped into Frames (`Frame4K`, `Frame2M`, `Frame1G`) or sub-Untypeds.
   - Any attempt to carve execution contexts (`TCB`), endpoints, or capability tables (`CNode`) out of device MMIO is rejected with `SeL4Error::IllegalOperation`.

6. **Revocation & Watermark Reset Soundness**:
   - Calling `seL4_CNode_Revoke` on an Untyped slot recursively destroys all derived child objects, sanitizes DRAM with physical memory zeroing, and resets the untyped `watermark` back to 0, returning the entire region to available capacity.

## 2. Verification Plan
- Unit tests & boot selftest:
  - Batch allocation of multiple frames and endpoints.
  - Watermark alignment progression: 16-byte object followed by 4 KiB object.
  - Sub-untyped creation and hierarchical delegation.
  - Out-of-memory exhaustion rejection (`SeL4Error::NotEnoughMemory`).
  - Lack of `WRITE` rights rejection (`SeL4Error::InsufficientRights`).
  - Device MMIO restriction rejection (`SeL4Error::IllegalOperation`).
  - Revocation, physical zeroing, and watermark reset.
- Verification gates:
  - `cargo check --release -p kernel --target x86_64-unknown-none`.
  - `cargo test --workspace`.
  - `python tools/claims_lint.py`.
  - `python tools/verify_findings.py`.
