# Design Note: Task A7 — Multi-NIC Drivers (e1000, VirtIO-Net, RTL8139)

> Revalidation on 2026-10-20 found that the implementation described below is
> not safe to activate. It is retained as a target design, not a statement of
> current support. Driver initialization and NIC probing now fail closed until
> DMA-safe physical memory and verified IOMMU isolation are available. See
> [`../EVIDENCE/A7.md`](../EVIDENCE/A7.md).

## Context & Objectives
KashOS targets a wide range of hardware platforms:
- **T0 Baseline / Vintage PC**: Intel Pentium III / 4 / Core 2 Duo with Realtek RTL-8139 Fast Ethernet (`-net nic,model=rtl8139`).
- **T1 Modern Bare Metal**: Intel Gigabit Ethernet (`82540EM`, `82545GB`, `82574L`) with DMA descriptor rings.
- **Virtual Machines**: VirtIO-Net (`0x1AF4:0x1000` / `0x1041`) paravirtualized network adapters with split virtqueues.

Prior to this task:
- `VirtioNetDevice::transmit_frame` and `Rtl8139Device::transmit_frame` were stubs (`let _ = frame; Ok(())`) that did not touch hardware descriptors or rings.
- Neither VirtIO-Net nor RTL8139 had a `receive_frame` implementation.
- `NetworkDriverSubsystem::receive` only queried `e1000`, ignoring packets received by VirtIO-Net or RTL8139.
- `RTL8139` status was omitted from `StatusRegistry`.

## Architecture & Implementation Strategy

### 1. Realtek RTL-8139 Driver (`Rtl8139Device`)
- **Registers**:
  - `TSD0..TSD3` (`io_base + 0x10 + 4*i`): Transmit status & length descriptor.
  - `TSAD0..TSAD3` (`io_base + 0x20 + 4*i`): Transmit start physical address.
  - `RBSTART` (`io_base + 0x30`): Physical base of continuous 8 KiB + 16-byte wrap ring buffer.
  - `CAPR` (`io_base + 0x38`): Current Address of Packet Read offset.
  - `CBR` (`io_base + 0x3A`): Current Buffer Address (written by hardware).
  - `CR` (`io_base + 0x37`): Command register (Reset `0x10`, RE `0x08`, TE `0x04`, Buffer Empty `0x01`).
  - `RCR` (`io_base + 0x44`): Receive Configuration Register (WRAP `0x80`, AAP, APM, AM, AB `0x0F`).
  - `MSR` (`io_base + 0x58`): Media Status Register (`MSR_LINKB = 1 << 2` indicates link down when set).
- **Reception**:
  - Polls `CR` for pending packet (`CR_BUFE == 0`).
  - Inspects 4-byte packet header at `rx_offset` (`status: u16`, `length: u16`).
  - Copies packet data minus 4-byte Ethernet CRC into destination buffer.
  - Advances `rx_offset = (rx_offset + length + 4 + 3) & !3` modulo 8192 and updates `CAPR`.
- **Transmission**:
  - Rotates across 4 hardware descriptors (`tx_cur = 0..3`).
  - Writes packet buffer physical address to `TSAD[tx_cur]`, and byte count to `TSD[tx_cur]`.
  - Tracks TX packets and bytes.

### 2. VirtIO-Net Driver (`VirtioNetDevice`)
- **Split Virtqueue**:
  - Queue 0: Receive Virtqueue (`rx_vq`).
  - Queue 1: Transmit Virtqueue (`tx_vq`).
  - 10-byte `virtio_net_hdr` (`flags`, `gso_type`, `hdr_len`, `gso_size`, `csum_start`, `csum_offset`).
- **Reception & Transmission**:
  - Sets up legacy VirtIO I/O ports (`Queue Select 0x0E`, `Queue Address 0x08`, `Queue Size 0x0C`, `Queue Notify 0x10`, `Device Status 0x12`).
  - Implements queue notification and ring processing for transmitting and receiving frames without heap allocation.

### 3. Subsystem Dispatch & Registry Tracking
- `NetworkDriverSubsystem::transmit` and `receive` dispatch across e1000, VirtIO, and RTL8139 in probe order.
- `StatusRegistry` gains `nic_rtl8139`, ensuring every NIC probed and active reports `Real` honestly.
- Shell and diagnostics report all 3 NIC families with MAC address and link state.
