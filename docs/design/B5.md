# B5: Asynchronous Notifications & Event Signaling

## Overview

Milestone B5 implements seL4-compliant asynchronous notification objects
(`seL4_NotificationObject`), bitwise event accumulation, and non-blocking
event signaling.

Unlike synchronous Endpoints where senders rendezvous with receivers,
Notifications provide non-blocking signaling: senders bitwise OR their badge
into an atomic event word, which is accumulated until a receiver consumes it.

## seL4 Architecture Reference

Reference: seL4 Reference Manual v16.0.0, §2.3 (Notifications) & §4.3 (Notification Objects).

### 1. Notification States

A notification object resides in one of three states:
- **`Idle`**: Event word is 0; no threads are waiting.
- **`Active`**: Event word is non-zero (events have accumulated); no threads are waiting.
- **`Waiting`**: Event word is 0; one or more threads are blocked waiting for signals.

### 2. Notification Invariants & Operations

- **`seL4_Signal(notification_cap)`**:
  - Requires `CapRights::WRITE`.
  - Computes `signal_badge = if cap.badge != 0 { cap.badge } else { 1 }`.
  - If a thread is in `Waiting` state:
    - Dequeues waiting thread and unblocks it.
    - Delivers `signal_badge` to the waiting thread.
    - Notification returns to `Idle` (word is cleared to 0).
  - If no thread is waiting:
    - Accumulates into the event word: `state |= signal_badge`.
    - Notification transitions to `Active`.
    - Calling thread continues execution immediately without blocking.
- **`seL4_Wait(notification_cap)`**:
  - Requires `CapRights::READ`.
  - If notification is `Active`:
    - Atomically extracts accumulated event word.
    - Resets event word to 0 (`state = 0`).
    - Notification transitions to `Idle`.
    - Calling thread receives accumulated word immediately without blocking.
  - If notification is `Idle`:
    - Calling thread is enqueued onto notification queue and suspended (`BlockedOnNotification`).
    - Notification transitions to `Waiting`.
- **`seL4_Poll(notification_cap)`**:
  - Non-blocking check for pending signals:
    - If `Active`: extracts word, clears state to 0, transitions to `Idle`.
    - If `Idle`: returns 0 immediately without blocking.

### 3. Bitwise Event Multiplexing

Multiple independent event producers can be granted differently-badged capabilities
to the same notification object:
- Producer 1 holds badge `0x0001` (e.g. Timer IRQ).
- Producer 2 holds badge `0x0002` (e.g. Network Packet IRQ).
- Producer 3 holds badge `0x0004` (e.g. Disk Controller IRQ).
Each producer calls `seL4_Signal`. The notification accumulates them: `0x0001 | 0x0002 | 0x0004 = 0x0007`.
When the driver consumer calls `seL4_Wait`, it receives `0x0007` and can inspect individual bits to dispatch handlers concurrently.
