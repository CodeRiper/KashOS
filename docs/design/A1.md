# Design Note: Task A1 — Remove Fake Network and Tor Output

## Motivation & Findings
Findings F1 and F2 revealed that `kernel/src/net.rs` returned simulated HTTP responses with canned HTML ("Congratulations. This browser is configured to use Tor"), a fake Tor-Exit-Proxy header, a hard-coded static host table with fallback Tor exit IP `104.244.76.13`, and a fake arithmetic RTT in `ping`.
A fake "You are using Tor" indicator is a severe safety hazard (Rule R1, R2, R10).

## Architecture Changes
1. **kernel/src/net.rs**:
   - Add `NetError::NotAvailable` to the `NetError` enum.
   - `http_get()`: Delete the canned HTML response blocks and return `Err(NetError::NotAvailable)` until real networking is linked in A6.
   - `dns_resolve()`: Delete the static host table and fallback IP. Only parse direct dotted-decimal IPv4 literals if valid, else return `None` (or `Err(NetError::NotAvailable)`).
   - `ping()`: Remove the simulated arithmetic RTT calculation (`120 + ((seq * 37) % 65)`); return `Err(NetError::NotAvailable)`.
   - Update `net status` to print `network: not available`.
2. **kernel/src/browser.rs**:
   - Remove `about:tor`.
   - Scrub fake sentences claiming active Tor circuits or 100% blocked trackers.
   - Update `about:kashos` to display honest runtime capability metrics from the status registry.
3. **UI and Shell**:
   - In `kernel/src/shell.rs`, remove references to Tor circuits in `route`, `curl/wget`, `traceroute`, `kash update`.
   - In `kash-ui`, scrub unbacked Tor / Anonymity Gateway claims from lock screens and settings panes.
4. **Linter Gate**:
   - In `tools/claims_lint.py`, enforce strict scanning for `Tor-Exit`, `Congratulations. This browser`, `204.8.99.100`, `104.244.76.13`, and literal `Some([` in `net.rs`.
