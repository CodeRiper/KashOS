# A1 design: disable unverified remote access

## Decision

Remote web requests must fail closed while DNS, TCP transport, TLS, certificate
validation, and response parsing are incomplete. The current framing helpers
are not a TLS implementation. A TLS record header cannot encrypt or
authenticate arbitrary HTTP bytes, and a ClientHello without a completed,
authenticated handshake cannot establish HTTPS.

## Implementation

- `NetworkService::http_get` returns `NetError::NotAvailable` without sending
  packets or manufacturing a response.
- Network initialization leaves the gateway down. Socket listings contain
  only sockets created by the stack.
- The local HTML parser is described as a prototype. Remote failures do not
  substitute a local page as if it were the requested site.
- Graphical browser launchers return an explicit unavailable error until they
  render actual pages in a separately isolated process.
- CI runs `tools/test_network_fail_closed.py` to guard these properties.

## Reopening the gate

Do not enable remote access by changing the status flag. First implement and
test real DNS, TCP, TLS 1.3 (including certificate and hostname validation),
HTTP parsing, and an enforced egress policy. Tests must cover handshake and
certificate failures, unreachable peers, malformed responses, and the
configured QEMU NIC path. Record exact versions, target configuration, and
packet/boot evidence in a new task evidence file.
