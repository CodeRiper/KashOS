# Design Note: T-F13 (Remove Fake Hardware Simulation)

**Task ID**: T-F13  
**Date**: 2026-10-18  
**Author**: Builder Agent  
**Guide Reference**: KashOS Build Guide v2, Section 5 (F-13), Finding V-12  

---

## 1. Objective
Remove simulated hardware strings in device initialization:
1. In `kernel/src/arch/x86_64/input.rs`, eliminate the hardcoded device pushes in `XhciController::init`:
   - Delete `connected_devices.push(String::from("RootHub-USB3..."))`
   - Delete `connected_devices.push(String::from("HID Keyboard..."))`
   - Delete `connected_devices.push(String::from("HID Optical Mouse..."))`
2. Report honestly on PCI discovery:
   - When PCI Class 0x0C (USB) is detected, print:
     `[xhci] USB host controller discovered @ BDF {:02x}:{:02x}.{:x} (MMIO {:#010x}): driver not implemented (deferred to Phase H / Phase 4)`
   - Mark status in `status.rs` as `NotAvailable("Driver not implemented; PS/2 active for T0")`.
3. Verify that real input is driven by the functioning PS/2 controller on T0.

---

## 2. Approach & Implementation Steps

### A. Modify `XhciController::init`
- Set `is_running = false`.
- Do not push fake device strings.
- Return `Err("USB host controller found, driver not implemented")` or log that the USB driver is not implemented.

### B. PCI Scanning in `input::init`
- Check PCI subclass (0x03) and ProgIF (0x30 for xHCI, 0x20 for EHCI, 0x00 for UHCI, 0x10 for OHCI).
- On discovery, log honest hardware presence without claiming working input devices over USB.

---

## 3. Risks & Mitigations
- **Risk**: Does kash-ui or compositor depend on `connected_devices`?
- **Mitigation**: Verified: `kash-ui` receives input events via `poll_input_event()`, which queries `Ps2Controller`. PS/2 keyboard and mouse are fully working and tested on QEMU and real hardware.

---

## 4. Still False / Partial / Not Done Afterwards
- Real user-mode USB stack (UHCI/EHCI for T0 baseline, xHCI for modern machines) will be implemented as an isolated service in Phase 4 / Phase H.
