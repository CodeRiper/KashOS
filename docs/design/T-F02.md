# Design Note: T-F02 (Hardware Feature Detection & Clean Refusal in Boot Stub)

**Task ID**: T-F02  
**Date**: 2026-10-18  
**Author**: Builder Agent  
**Guide Reference**: KashOS Build Guide v2, Section 5 (F-02), Section 3 (T0 Hardware Targets), Finding V-14  

---

## 1. Objective
Ensure KashOS detects unsupported 32-bit or non-NX CPUs before transitioning to 64-bit mode:
1. In `kernel/src/arch/x86_64/boot.S`, execute rigorous CPUID checks before configuring PAE, PML4, or writing EFER.
2. Validate mandatory hardware features:
   - CPUID availability (EFLAGS bit 21 toggle)
   - MSR support (CPUID.1:EDX[5])
   - PAE support (CPUID.1:EDX[6])
   - APIC on-chip (CPUID.1:EDX[9])
   - FXSR support (CPUID.1:EDX[24])
   - SSE2 support (CPUID.1:EDX[26])
   - Extended CPUID availability (CPUID 0x80000000 >= 0x80000001)
   - Long Mode / 64-bit support (CPUID.0x80000001:EDX[29])
   - NX / Execute Disable support (CPUID.0x80000001:EDX[20])
3. If any check fails, cleanly print an informative error to:
   - VGA text framebuffer (`0xB8000`, white-on-red `0x4F`)
   - Serial COM1 (`0x3F8`)
   Then cleanly halt with `cli; hlt` instead of triple-faulting into a reset loop.
4. Provide a structured `CpuFeatures` record in Rust populated during early initialization.

---

## 2. Approach & Implementation Steps

### A. Assembly Checks in `boot.S` (32-bit Protected Mode)
Before enabling PAE in CR4 (`mov eax, cr4; or eax, 0x20`) and writing EFER:
```nasm
    /* 1. Test CPUID support via EFLAGS bit 21 */
    pushfd
    pop   eax
    mov   ecx, eax
    xor   eax, 0x200000
    push  eax
    popfd
    pushfd
    pop   eax
    push  ecx
    popfd
    cmp   eax, ecx
    je    _no_cpuid_err

    /* 2. Check standard CPU features: MSR, PAE, APIC, FXSR, SSE2 */
    mov   eax, 1
    cpuid
    test  edx, (1 << 5)   /* MSR */
    jz    _no_msr_err
    test  edx, (1 << 6)   /* PAE */
    jz    _no_pae_err
    test  edx, (1 << 9)   /* APIC */
    jz    _no_apic_err
    test  edx, (1 << 26)  /* SSE2 */
    jz    _no_sse2_err

    /* 3. Check extended CPU features: Long Mode and NX */
    mov   eax, 0x80000000
    cpuid
    cmp   eax, 0x80000001
    jb    _no_longmode_err

    mov   eax, 0x80000001
    cpuid
    test  edx, (1 << 29)  /* Long Mode (LM) */
    jz    _no_longmode_err
    test  edx, (1 << 20)  /* No-Execute (NX) */
    jz    _no_nx_err
```

### B. Output Routine on Failure
- Output string to COM1 (`0x3F8`) using polling on Line Status Register (`0x3FD`, bit 5 THRE).
- Write characters to VGA text mode memory at physical `0xB8000` with attribute `0x4F` (white text on red background).
- Format:
  `"KashOS: This CPU lacks x86_64 Long Mode with NX. 64-bit CPU required. System halted."`
- Execute:
  ```nasm
  _cpu_halt:
      cli
      hlt
      jmp _cpu_halt
  ```

---

## 3. Risks & Mitigations
- **Risk**: Does COM1 need initialization if bootloader didn't set it up?
- **Mitigation**: Perform a minimal COM1 init (set DLAB=0, 8N1) in the failure handler before transmitting characters so serial output is reliably emitted even without BIOS serial redirection.
