# B7 Design Document: Mixed-Criticality Scheduling (MCS): SchedContext & Temporal Isolation

## 1. Architectural Overview

In classical seL4 and conventional microkernels, scheduling priority is tied directly to the thread (TCB), and time is unmanaged or managed through coarse round-robin time slices. This model is vulnerable to denial-of-service, priority inversion, and temporal starvation: a rogue low-criticality or untrusted thread can monopolize the CPU, starving safety-critical or real-time tasks.

KashOS Milestone B7 implements the **seL4 Mixed-Criticality Systems (MCS)** scheduling architecture. Under MCS:
1. **Time is a First-Class Capability**: CPU execution time is decoupled from execution state (TCB) and encapsulated in an explicit kernel capability: `SchedContext` (`seL4_SchedContext`).
2. **Passive Threads**: A thread without a bound scheduling context (`is_passive == true`) possesses state and registers but zero CPU time. It cannot be scheduled on its own.
3. **Temporal Isolation & Sporadic Server**: Each `SchedContext` defines a strict execution budget $C$ (`budget_us`) and period $T$ (`period_us`), guaranteeing that a subsystem can consume at most $C/T$ fraction of CPU time, preventing timing side-channels and CPU starvation.
4. **Time Donation across Synchronous IPC**: When a client thread invokes a passive server (such as an in-kernel security monitor, filesystem, or cryptographic driver) via `seL4_Call`, the client's scheduling context is temporarily **donated** to the server. The server executes on the client's budget and priority, preventing server starvation without requiring ambient server budgets. Upon `seL4_Reply`, time returns to the client.

## 2. Kernel Types & Data Structures

### 2.1 `SchedContextObject`

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct ReplenishmentItem {
    pub time_us: u64,
    pub amount_us: u64,
}

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct SchedContextObject {
    pub sc_id: u64,
    pub budget_us: u64,
    pub period_us: u64,
    pub remaining_budget_us: u64,
    pub bound_tcb_id: Option<u64>,
    pub badge: u64,
    pub is_sporadic: bool,
    pub last_replenished_us: u64,
    pub replenishment_deadline_us: u64,
}
```

### 2.2 TCB Integration

In `TcbObject`:
- `is_passive: bool`: `true` if thread does not own an active scheduling context.
- `sched_context_slot: Option<usize>`: Index of the bound `SchedContext` capability.
- `donated_sched_context_slot: Option<usize>`: Index of a temporarily donated `SchedContext` received during IPC.

## 3. Scheduling Invariants & Core Operations

### 3.1 Invariant Rules

- **I-MCS-1 (Budget Invariant)**: For all valid `SchedContextObject` instances, $0 < \text{budget\_us} \le \text{period\_us}$.
- **I-MCS-2 (Temporal Monotonicity)**: Execution charge can only decrease `remaining_budget_us` until replenished: $\text{remaining\_budget\_us} \le \text{budget\_us}$.
- **I-MCS-3 (Exclusive Binding)**: A `SchedContext` can be bound to at most one TCB at any time. A TCB can have at most one primary bound `SchedContext`.
- **I-MCS-4 (Passive Thread Inertia)**: A thread with `is_passive == true` and `donated_sched_context_slot == None` shall never be placed into the active scheduler run-queue.
- **I-MCS-5 (Donation Restitution)**: When a server thread completes handling an IPC request and issues a reply, the donated scheduling context must be returned to the client immediately.

### 3.2 System Call Operations

1. **`sched_context_configure(sc_slot, budget_us, period_us, badge)` (`seL4_SchedContext_Configure`)**:
   - Validates that `budget_us > 0` and `budget_us <= period_us`.
   - Requires `WRITE` right on `sc_slot`.
   - Initializes `remaining_budget_us = budget_us`.

2. **`sched_context_bind(sc_slot, tcb_slot)` (`seL4_SchedContext_Bind`)**:
   - Requires `WRITE` on both `sc_slot` and `tcb_slot`.
   - Binds `sc_id` to the target `tcb_id`.
   - Updates target TCB: `is_passive = false`, `sched_context_slot = Some(sc_slot)`.

3. **`sched_context_unbind(sc_slot)` (`seL4_SchedContext_Unbind`)**:
   - Requires `WRITE` on `sc_slot`.
   - If bound to a TCB, disassociates the context and sets TCB `is_passive = true`.

4. **`sched_context_charge(sc_slot, elapsed_us)`**:
   - Deducts `elapsed_us` from `remaining_budget_us`.
   - If `remaining_budget_us == 0`, thread is suspended until the replenishment period.

5. **`sched_context_replenish(sc_slot, current_time_us)`**:
   - Checks if `current_time_us >= replenishment_deadline_us`.
   - Resets `remaining_budget_us = budget_us`, moving deadline to `current_time_us + period_us`.

6. **`sched_context_donate(donor_tcb_slot, recipient_tcb_slot)` & `sched_context_return`**:
   - Transfers execution capability during synchronous IPC rendezvous.
   - Recipient executes with donor's budget.
   - Upon completion, context restores to donor.

## 4. Acceptance Criteria & Test Matrix (Test 53)

1. **Object Allocation & Sizing**: Retype Untyped memory into `SchedContext` and `TCB` objects.
2. **Configuration Validation**: Verify rejection of `budget == 0` or `budget > period`.
3. **Passive Thread Invariant**: Verify newly minted passive thread cannot run without SchedContext.
4. **Binding & Runnable State**: Bind SchedContext to passive thread; verify thread transitions to runnable.
5. **Execution Charging & Budget Exhaustion**: Simulate consumption; verify budget decrements and thread exhausts when reaching 0.
6. **Temporal IPC Donation**: Test synchronous call from client to passive server; verify server runs on client's budget and budget returns to client on reply.
7. **Periodic Replenishment**: Advance simulated clock; verify budget is restored.
8. **Unbinding**: Disassociate context; verify thread returns to passive state.
9. **CDT Invariant Preservation**: Ensure derivation tree invariants (I1–I5) remain strictly intact.
