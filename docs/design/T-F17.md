## 1. Objective
Eliminate repository hygiene and privacy violations:
1. Untrack committed 23 MB kernel binary (`isodir/boot/kash-kernel`) from git tracking and ensure `.gitignore` covers `isodir/boot/*`, `*.iso`, `*.img`, `*.ppm`.
2. Add root `LICENSE` file (MIT License).
3. Add `THIRD_PARTY_NOTICES.md` with explicit licenses for bundled fonts (Inter under SIL OFL 1.1, DejaVu under DejaVu License) and core dependencies.
4. Create single source of truth `VERSION` file (`0.1.0`) consumed by build scripts and manifests.
5. Cleanse `file:///C:/Users/<user>/...` links in `docs/` and replace with proper repo-relative markdown links (`[`file`](path)`).
6. Update Cargo profiles with `--remap-path-prefix` and symbol stripping so personal paths do not leak into release binaries.
7. Pin `rust-toolchain.toml` correctly with `rust-src` and `llvm-tools-preview`.

---

## 2. Approach & Implementation Steps

### A. Git Tracking & Ignore Rules
- Run `git rm --cached isodir/boot/kash-kernel`.
- Ensure `.gitignore` explicitly ignores:
  ```gitignore
  isodir/boot/*
  !isodir/boot/.gitkeep
  *.iso
  *.img
  *.ppm
  ```

### B. Licensing & Font Notices
- Add `LICENSE`: Standard MIT license attributed to Akash (`akash.official.j@gmail.com`).
- Add `THIRD_PARTY_NOTICES.md`:
  - SIL Open Font License 1.1 text for Inter.
  - DejaVu Fonts License text for DejaVu Sans Mono / DejaVu Sans.
  - Rust crate dependency license summaries.

### C. Single Version Source (`VERSION`)
- Create `VERSION` containing `0.1.0`.
- Harmonize workspace Cargo manifests so version strings agree.

### D. Documentation Path Sanitization
- Scan `docs/` and `README.md` for `file:///C:/Users/<user>/...`.
- Replace all occurrences with relative markdown paths (e.g. `[kash-ui](kash-ui)` or `[README](README.md)`).

### E. Toolchain & Profile Hardening
- Update `rust-toolchain.toml` with channel and required components.
- In `Cargo.toml`, configure release profile:
  ```toml
  [profile.release]
  debug = false
  strip = "symbols"
  panic = "abort"
  overflow-checks = true
  ```

## 3. Risks & Mitigations
- **Risk**: Untracking `isodir/boot/kash-kernel` might cause scripts relying on a prebuilt binary in fresh clones to fail unless `cargo build` is run.
- **Mitigation**: Update build scripts / Makefile / README instructions to ensure `make iso` or `cargo build --release -p kernel` is called first.
