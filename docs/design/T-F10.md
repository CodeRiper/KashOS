# Design Note: T-F10 (Rename Formal Invariants to Property Tests)

**Task ID**: T-F10  
**Date**: 2026-10-18  
**Author**: Builder Agent  
**Guide Reference**: KashOS Build Guide v2, Section 5 (F-10), Finding V-08  

---

## 1. Objective
Eliminate deceptive wording regarding formal verification:
1. Rename `kcore/tests/formal_invariants.rs` to `kcore/tests/capability_property_tests.rs`.
2. Refactor doc comments and test function names inside the test file to describe them honestly as property/unit tests rather than mathematical theorems or formal proofs.
3. Update `docs/CLAIMS.md`, `README.md`, and any related documentation to remove unbacked claims like "machine-checked formal invariant proofs" until real Kani/Verus harnesses are added in `proofs/` (Phase 10).
4. Demote the capability invariants claim row in `docs/CLAIMS.md` from "Proven" or misleading evidence levels to honest "Tested (E1/E2)".

---

## 2. Approach & Implementation Steps

### A. Rename Test File
- Use `git mv kcore/tests/formal_invariants.rs kcore/tests/capability_property_tests.rs`.
- Rename function prefixes from `formal_invariant_*` to `property_test_*`.
- Update header comment to describe exhaustive algorithmic property testing.

### B. Documentation Cleansing
- In `docs/CLAIMS.md`:
  - Replace `formal_invariants.rs` references with `capability_property_tests.rs`.
  - Demote "Parts are formally verified & hardened" to "Capability Property Tests & Boundary Hardening", with evidence level E1 (host unit/property tests) + E2 (in-kernel self-tests).
  - Cleanse unbacked words ("machine-checked", "formal proofs") from milestone notes.
- In `README.md`:
  - Update any mentions of `formal_invariants.rs` to `capability_property_tests.rs`.

---

## 3. Risks & Mitigations
- **Risk**: Renaming test file might break references in CI or Cargo scripts.
- **Mitigation**: Cargo automatically discovers tests in `tests/*.rs`. Running `cargo test -p kcore` will verify test discovery and execution.

---

## 4. Still False / Partial / Not Done Afterwards
- Real machine-checked proofs using Kani/Verus/Coq in `proofs/` are deferred to Phase 10 as specified in the Build Guide roadmap.
- No code claim will be labeled "Proven" until a proof artifact exists in `proofs/` and runs in CI.
