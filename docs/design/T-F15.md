## 1. Context & Defect (Finding V-17)

Finding V-17 of Build Guide v2 observed:
- 26 kernel source files carried `#![allow(dead_code)]`, suppressing compiler lints about unused, ornamental, or uncalled model code.
- `kernel/src/kash_kernel.rs` was an unused 345-line model file defining untyped memory watermark allocator and ARINC 653 cyclic scheduler structs that were never linked or invoked by the runtime microkernel boot path.
- `kernel/src/shell.rs` contained commands that printed `Simulating...` (e.g. `fault-test` and `speakersafetyd`) or printed unconditional checkmarks (`✓`) indicating fake hardware verification.
- `kernel/src/selftest.rs` and other kernel modules contained 58 instances of `kprintln!` output emitting `✓` checkmarks or `[OK]` outside `status.rs`, violating Appendix A and Rule 3 ("No fake [OK]").

---

## 2. Approach & Cleanups

### 2.1 Purge Simulated Shell Commands & Strings
- **`fault-test` in `kernel/src/shell.rs`**:
  Replace `Simulating unexpected firmware fault...` and fake `✓ Verification...` prints with honest driver fault containment invocation logging:
  `[test] Driver fault containment test: triggering Wi-Fi supervisor fault handler...`
- **`safety` / `speakersafetyd` in `kernel/src/shell.rs`**:
  Remove `Simulating Audio Frame Processing through DSP Filter...`. When invoked on x86-64 / PC hardware where Apple Silicon TAS2764 is absent, report honestly:
  `[speakersafetyd] NotAvailable: Apple Silicon hardware (TAS2764) not detected on this architecture.`
- **Sanitize Shell Output**:
  Replace `✓` checkmarks in clipboard (`kctl`), powerbox, and installation wizard with honest status strings (e.g., `[kctl] Clipboard delivered sanitized UTF-8...`, `[powerbox] Access GRANTED...`, `[stage-N] Hardware probed...`).

### 2.2 Purge Checkmarks Outside `status.rs`
- **`kernel/src/selftest.rs`**:
  Replace all `kprintln!("[selftest] ✓ T...` with `kprintln!("[selftest] PASS: T...`. Tests honestly report their completion without violating Appendix A prohibition against `[OK]` and `✓` outside `status.rs`.
- **`kernel/src/vfs.rs`**:
  Replace `✓ Existing kvault root volume unlocked` with clean informational text:
  `[vfs] Existing kvault root volume unlocked successfully`.
- **`kernel/src/arch/x86_64/clock.rs` & `fpu.rs`**:
  Remove `✓` from TSC calibration and SSE enablement logs.

### 2.3 Model File `kash_kernel.rs`
- Remove unused model crate module `kash_kernel.rs` from `kernel/src/main.rs`.
- Place model specifications under appropriate unit test or documentation context, ensuring the kernel binary only links executable, runtime-active code.

### 2.4 Dead Code Allow Directives
- Remove `#![allow(dead_code)]` from kernel source files.
- Where specific types/methods are legitimate public APIs awaiting userland consumption (Phase U), annotate specific items with targeted `#[allow(dead_code)]` or preserve them cleanly without blanket file-level silencing.

---

## 3. Risks & Mitigations
- **Compiler warnings on unused functions**: When blanket `#![allow(dead_code)]` is removed, the compiler identifies genuinely dead code. Any genuinely unused dead functions will be deleted or marked with targeted items.

---

## 4. What Will Still Be False / Partial / Not Done Afterwards
- Driver services in Phase 4 are still linked into the kernel binary until Phase 4 separates them into isolated user processes.
- Status registry continues to honestly report `NotAvailable` for absent hardware.
