# Design Note: Task A10 — User-Space Services and Ring 3 Transition

## Current design status

The previous A10 design described a Ring 3 compositor and shell as implemented.
Source review found that `session.rs` called both services directly in Ring 0,
and its capability-space initialization only wrote synthetic model objects.
Those implementation claims have been withdrawn. See
[`../EVIDENCE/A10.md`](../EVIDENCE/A10.md).

The running architecture is currently:

```text
Ring 0: kernel, session handoff, desktop compositor, settings, console shell
   |
   +-- tested separately: hand-built Ring 3 process + syscall mechanism
       (self-test only; not the normal desktop or shell boot path)
```

## Requirements before A10 can be marked complete

1. Provide a trusted user-mode init/session manager that loads real ELF images.
2. Allocate and map user code, data, and stacks from verified physical frames;
   keep kernel mappings supervisor-only and validate the transition frame.
3. Create per-process CSpaces from real capabilities with least authority.
   Do not seed spaces with fabricated physical addresses or `Rights::ALL`.
4. Connect process creation, scheduler state, CR3 switching, TSS kernel stacks,
   syscall dispatch, IPC, and fault cleanup into one tested lifecycle.
5. Move the shell and desktop/compositor into separately fault-contained user
   processes. Keep framebuffer and input access mediated by kernel capabilities.
6. Add QEMU integration tests that prove the normal boot session enters Ring 3,
   validates user CS/SS and CR3, rejects unauthorized access, and survives a
   crashed service without panicking the kernel.
7. Only report A10 complete after the production boot path and CI tests prove
   these properties. Self-test execution alone is not sufficient evidence.
