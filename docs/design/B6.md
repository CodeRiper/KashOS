# B6: Thread Control Blocks (TCBs), Fault Handlers & State

## Overview

Milestone B6 implements the seL4 Thread Control Block (`seL4_TCBObject`), thread
execution state lifecycle, register management, fault endpoint routing, and
priority/MCP authority bounding.

A TCB represents an execution context within a microkernel protection domain.
Unlike monolithic OSes, thread creation in seL4 decouples resource allocation
from thread configuration: memory is allocated via Untyped retyping, followed
by explicit CSpace, VSpace, fault handler, and register configuration.

## seL4 Architecture Reference

Reference: seL4 Reference Manual v16.0.0, §2.4 (Threads of Execution) & §6.1 (Thread Control Blocks).

### 1. Thread Execution States (`ThreadState`)

A TCB resides in one of the following states:
- **`Inactive`**: Initial state after Untyped retype; unconfigured, cannot be scheduled.
- **`Ready` / `Running`**: Fully configured and eligible for CPU execution by the scheduler.
- **`BlockedOnReceive`**: Blocked awaiting synchronous IPC on an Endpoint.
- **`BlockedOnSend`**: Blocked awaiting rendezvous with an Endpoint receiver.
- **`BlockedOnReply`**: Blocked awaiting a single-use Reply after `seL4_Call`.
- **`BlockedOnNotification`**: Blocked awaiting asynchronous notification signals.
- **`Suspended`**: Paused explicitly via `seL4_TCB_Suspend`.
- **`Restart`**: Awaiting resumption following fault resolution.

### 2. TCB Capabilities & Privileges

A TCB capability (`CapKind::TCB`) grants rights over the targeted thread:
- `CapRights::WRITE`: Required to configure TCB, write registers, suspend, and set priority.
- `CapRights::READ`: Required to read registers and inspect thread state.
- `CapRights::GRANT`: Required to bind notification objects and transfer capability roots.

### 3. TCB Configuration (`seL4_TCB_Configure`)

Configures a thread's isolated environment:
- **`cspace_root`**: Root CNode governing thread capability resolution.
- **`vspace_root`**: Virtual address space root (CR3 / PML4).
- **`fault_ep`**: Endpoint capability where thread exceptions and faults are delivered as IPC messages.
- **`ipc_buffer_vaddr`**: Virtual address of the 4 KiB IPC buffer page.

### 4. Maximum Controlled Priority (MCP) Invariant

seL4 enforces strict capability-based authority bounds on thread scheduling:
- Every TCB possesses a `priority` (0..255) and an `mcp` (Maximum Controlled Priority, 0..255).
- **MCP Invariant**: When Thread A modifies the priority of Thread B via `seL4_TCB_SetPriority(B, new_prio)`:
  - `new_prio <= A.mcp`
  - A thread can never elevate any thread's priority beyond its own Maximum Controlled Priority.

### 5. Fault Handling Architecture

When a thread encounters an unhandled fault (e.g. invalid capability access, VM page fault, or CPU exception):
- The kernel suspends the faulting thread (`ThreadState::Suspended`).
- The kernel formats an IPC fault message containing:
  - `label`: Fault type (`CapFault`, `VmFault`, `UnknownSyscall`, `UserException`).
  - Registers snapshot (`rip`, `rsp`, fault address, error code).
- The message is sent to the thread's configured `fault_ep`.
- The fault handler thread inspects the fault, repairs the condition (e.g. maps a page or updates capability), and resumes the faulting thread.
