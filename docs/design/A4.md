# Design Note: Task A4 — Real TPM 2.0 Driver (TIS First, CRB Second)

## Motivation & Findings
Finding F5 documented that `kernel/src/arch/x86_64/tpm.rs` implemented a software PCR array and RAM-based item table without sending actual TPM commands over hardware buses. The driver only read the DID/VID register once and then simulated PCR operations in host memory.

## Architectural Requirements
- **Rule R1 (Zero Simulation / Honest Claims)**: If hardware TPM 2.0 is present, communicate with it using standard TCG commands over MMIO. If absent, report honestly as `NotAvailable` rather than faking hardware execution.
- **Rule R2 (Fail-Closed Hardware Security)**: TPM access must timeout cleanly and fail-closed if registers are unresponsive or bus integrity is violated.
- **TIS (TPM Interface Specification) First**:
  - Memory-mapped I/O at base `0xFED4_0000` (Locality 0).
  - TIS register protocol:
    1. Request Locality 0 (`TPM_ACCESS` bit 1 `REQUEST_USE`). Wait for bit 5 (`ACTIVE_LOCALITY`).
    2. Command Ready handshake (`TPM_STS` bit 6 `COMMAND_READY`).
    3. Command byte transfer via `TPM_DATA_FIFO` (offset `0x0024`) with burst count pacing.
    4. Execution trigger via `TPM_STS` bit 5 (`GO`).
    5. Response wait (`TPM_STS` bit 4 `DATA_AVAIL`).
    6. Response header parse and payload read from FIFO.
    7. Release Locality 0.
- **CRB (Command Response Buffer) Second**:
  - For systems advertising CRB interface in ACPI TPM2 table.
  - Command buffer execution via Start Method control area.
- **TCG TPM 2.0 Command Set**:
  - `TPM2_Startup` (`0x00000144`)
  - `TPM2_GetRandom` (`0x0000017B`)
  - `TPM2_PCR_Read` (`0x0000017E`)
  - `TPM2_PCR_Extend` (`0x00000182`)

- QEMU boot test with TPM TIS MMIO mapping enabled.
