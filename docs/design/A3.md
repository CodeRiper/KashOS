# Design Note: Task A3 — Key Management Re-Audit

## Current source behavior

The implementation did not meet the stated passphrase-first, TPM-second
design. This revision removes the default-key boot path and adds a hidden
console passphrase prompt. It does not complete A3: the TPM handle had only
in-memory state and no persistent enrollment/recovery path. The KMS passphrase
transform is HKDF-SHA256 over a compiled-in salt; the encrypted vault's own
Argon2id KDF adds per-volume cost using stored parameters and salt.

## Safety constraints for future implementation

- Do not remove legacy key access until a tested migration preserves existing
  encrypted data.
- The historical default credential was public; old volumes using it are
  recoverable by manually entering it, but are not confidential against an
  attacker who knows the repository history.
- New installs must require user enrollment and must not boot with a shared
  default credential.
- Specify password KDF parameters and persist a unique salt in an authenticated
  format, with explicit versioning and recovery behavior.
- Treat TPM enrollment and unsealing as persistent object lifecycle work, not
  an in-memory handle flag. Test absent, locked, cleared, and policy-mismatch
  states on supported hardware or an accurately configured emulator.
- Do not expose the credential through command echo, logs, or shell history.
- Keep mount failures non-destructive throughout migration.

## Argon2 floor follow-up (2026-10-20)

The vault accepted structurally valid KDF profiles as small as 8 KiB for new
volumes. A 64 KiB `TEST_ONLY_INSECURE_FAST` profile was also referenced by the
kernel's boot self-test. This conflicts with the plan's A3 floor and makes a
test profile part of the normal runtime source.

New persistent vault formatting now requires at least 19 MiB and two passes
(OWASP floor: t=2, p=1) or a stronger profile. The low-memory legacy profile
uses 64 MiB, t=16, p=1 because
the library caps accepted time cost at 16. Existing low-cost volumes remain
readable through the normal open/recovery path; this change does not rewrite
or silently strand old data. The 64 KiB fixture is compiled only with the
explicit `test-fast-kdf` Cargo feature in debug builds. The kernel boot
self-test uses the supported 19 MiB profile.

Validation includes an invalid-format regression test, library tests with and
without the test-only feature, release kernel compilation, and the existing
T0 boot smoke test. The runtime boot self-test may run slower because its
ephemeral volume now uses the production floor.

## Status

A3 remains Needs revalidation. Console unlock is implemented; passphrase
enrollment, migration, a protected GUI flow, and persistent TPM provisioning
are not.

## Primary references

- [RFC 9106: Argon2 memory-hard function](https://www.rfc-editor.org/rfc/rfc9106.html)
  specifies Argon2id and discusses parameter selection for password hashing and
  disk-encryption key derivation. KashOS must choose and benchmark parameters
  for its supported hardware rather than copying the RFC's high-memory example
  blindly.
- [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
  currently gives Argon2id's minimum configuration as 19 MiB, t=2, p=1. This
  is the minimum for newly formatted KashOS vaults, not a denial of access to
  older encrypted volumes.
- [TCG TPM 2.0 Library Specification](https://www.trustedcomputinggroup.org/resources/documents/tpm-library-specification)
  is the authoritative command and object-lifecycle reference for a future
  persistent TPM enrollment implementation.
