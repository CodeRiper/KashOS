# Design Note: Task A18 — Make the UI Honest and Connected to Real Services

## Metadata
- **Task ID**: A18
- **Title**: Make the UI honest and connected to real services
- **Status**: Needs revalidation
- **Audit date**: 2026-10-20

## 1. Objectives & Specification
1. Every security or hardware status shown in Settings must be read from an
   implemented service or explicitly displayed as unavailable/experimental.
2. Network settings must not claim an Ethernet/IP/TCP/TLS/Tor path until the
   corresponding hardware and protocol implementations are connected and
   tested end to end.
3. Settings controls must call a real service; otherwise they must be removed
   from the release UI or disabled with an honest explanation.
4. Files, app registry, POST status, privacy controls, and security panes need
   independent source and runtime audits; old evidence is not sufficient.

## 2. Verification Plan
- Unit tests: `cargo test -p kash-ui` passes all tests.
- Target check: `cargo check --release -p kernel --target x86_64-unknown-none` compiles cleanly.
- Current focused work: correct stale networking claims in `settings.rs` and
  guard them with `tools/test_network_fail_closed.py`.
- Run `cargo test -p kash-ui`, the network honesty guard, claims linter, and the
  relevant QEMU boot test. Passing these checks does not complete A18.

## Outstanding work

The GUI is still a prototype and Settings are not generally connected to live
kernel services. A18 remains incomplete until each control and displayed
status is mapped to a real IPC/service path or removed from release builds.
- The privacy catalog contains only compiled-in UI demos. CLI and driver
  package inventory, package metadata, signature verification and runtime
  capability enforcement remain unavailable. Catalog controls change local
  demo state only and must not be described as execution or kernel policy.
- About and lock-screen hardware, identity, and security status must come from
  real services; until those services exist the UI uses generic identity and
  explicit unavailable/not-reported states. No live boot-test result service
  currently feeds the UI.
