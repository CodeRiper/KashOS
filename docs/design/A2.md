# Design Note: Task A2 — Stop the Data-Loss Bug (Vault Open vs Format)

## Findings

The mount path already refused to format when `Vault::open` failed, but its
boot-time acceptance test undermined that safeguard. When the root vault was
not mounted, T25 called `format_root`; if mounted, it wrote a test file and
modified raw sectors to simulate corruption. A normal boot test must never
format or corrupt a user's persistent volume.

## Invariants

- `mount_root` attempts to open the existing volume and returns an error on
  failure. It never formats as a fallback.
- `format_root` is an explicit installer/administrative operation.
- Boot-time storage checks are read-only. If the persistent vault is not
  mounted, T25 reports a skip.
- Wrong-key open non-mutation is tested on a disposable in-memory device.

## Implementation

1. Keep the existing fail-closed mount behavior.
2. Replace T25's implicit formatting, disk writes, and raw bit-flip with a
   read-only check of an already-mounted root volume.
3. Add `tools/test_storage_non_destructive.py` and run it in CI to guard the
   mount and boot-test invariants.
4. Retain the kvault wrong-password test that checks the returned device is
   bit-for-bit unchanged.
