## Original reproduced issue

The previous A1 evidence said fabricated network output was removed. Current `kernel/src/net.rs` contradicted that: `http_get` built a ClientHello with constant bytes, wrapped raw HTTP bytes in a TLS ApplicationData record, ignored send failures, and returned a locally generated HTML page claiming a secure connection when no response arrived. Network init also marked a synthetic anonymity gateway `Up`. The old `tools/verify_findings.py` returned 0/12 because it searches for stale strings and does not check these behaviors.

TLS 1.3 uses an authenticated handshake and protected records; adding a record header does not provide encryption/authentication ([RFC 8446](https://www.rfc-editor.org/rfc/rfc8446/)). smoltcp provides TCP/IP sockets and is not itself a TLS implementation ([smoltcp socket API](https://docs.rs/smoltcp/0.14.0/smoltcp/socket/)). Tor status must be established through an actual Tor-routed connection; a local label is insufficient evidence ([Tor Project connection check](https://check.torproject.org/)). Sources reviewed on 2026-10-20.

## Changes

- `NetworkService::http_get` returns `NetError::NotAvailable`; it sends no remote traffic and returns no synthetic page. The public gateway-state setter was removed so runtime code cannot mark an unimplemented tunnel up.
- The anonymity gateway uses the `Disabled` profile and starts down; network initialization no longer marks it up.
- Socket listings no longer fabricate Tor or encrypted DNS listeners.
- Browser UI labels the text parser as a KashOS prototype, removes unsupported privacy/security claims, and does not substitute local pages for failed remote requests. Graphical browser entrypoints explicitly return unavailable.
- Added `tools/test_network_fail_closed.py` to CI to guard the HTTP path, gateway state, and key browser claims.
- Initialized the heap before allocation-using boot tests and moved large packet rings off the small early boot stack.
- Corrected network boot tests to expect unavailable remote access. Reworded model-test output so helper checks are not presented as hardware or formal-assurance results.
- Updated the QEMU helper to prefer the freshly built release kernel; its earlier packaged-image preference could run a stale binary.
- The Part A and B0-B6 ledger entries that were previously marked Done are now “Needs revalidation” pending evidence review.

## Follow-up audit (2026-10-23)

The current network service still returns `NotAvailable` for remote HTTP,
blocks packet egress, rejects ingress, and labels its socket entries as a model.
The browser entrypoints for graphical browsing return unavailable. However,
`kernel/src/browser.rs` retained stale module documentation claiming tracker
elimination, authenticated pages, cookie sandboxing, and OpenBSD-style sandbox
controls. Its text-viewer output also used a secure-privacy browser title,
described a blacklist and kill-switch result that its current network service
cannot produce, and labeled parsed links as a safe-navigation sandbox.

This follow-up removes those assertions and simplifies the unreachable error
branches to report remote pages unavailable. `tools/test_network_fail_closed.py`
now rejects the stale phrases. The regression was run before the source fix and
failed on all nine initial assertions; it now passes 48 total network checks.
