# Evidence: Task A7 — NIC drivers

## Status

Needs revalidation. Audit date: 2026-10-20. The previous “Completed / Verified”
label was not supported by the source or test evidence. The drivers are disabled
until the kernel has DMA-safe physical allocations and a verified IOMMU path.

## Source findings

- e1000, VirtIO-Net and RTL8139 initialization previously converted Rust virtual
  pointers to device DMA addresses. The kernel has no DMA mapping allocator to
  establish that these are device-visible physical addresses.
- The PCI probe enabled bus mastering before driver setup and ignored driver
  initialization errors, then marked any allocated driver object `Real`.
- The e1000 path has no verified device MMIO mapping. VirtIO queue setup does
  not implement the required legacy queue memory layout. The RTL8139 receive
  ring accepts all packet classes, including promiscuous mode.
- Tests of packet headers and in-memory queues do not exercise DMA, NIC register
  behavior, link negotiation, packet ingress, or physical network traffic.
- A9 IOMMU code is not a verified DMA isolation mechanism. A7 cannot safely
  enable bus mastering before A9 and DMA allocation are completed.

## Fail-closed changes

- Per-device `init` methods return an unavailable error before any port or MMIO
  access; `is_up` is private and remains false.
- TX and RX reject inactive devices.
- The exported NIC initializer does not scan PCI, enable bus mastering, create
  adapters, or mark a NIC `Real`. It records the NIC implementations as `Stub`.
- Kernel network transport remains disabled as documented by A6.
- `tools/test_nic_dma_fail_closed.py` is run by CI to guard these conditions.

## Verification limits

The regression guard and kernel build can establish that unsupported NIC paths
stay disabled. They do not verify real NIC operation. Hardware support remains
unavailable pending a DMA allocator, a real IOMMU implementation, correct driver
protocols, and QEMU packet-capture plus physical-device testing.
