## 1. Summary of Completed Implementation
Milestone B0 initiates Part B of the KashOS Master Engineering Plan: Kash Kernel 2.0 (seL4-Class Microkernel in Rust). This milestone establishes the mathematical foundations of the capability system adhering strictly to the seL4 Reference Manual (v16.0.0):

1. **Orthogonal Access Rights (`CapRights` / `Rights`)**:
   - Implemented 4-bit orthogonal rights model across `kcore::Rights` and `kernel::cap::CapRights`:
     - Bit 0: `READ` (`0x1`) — authority to observe object state or read frame memory.
     - Bit 1: `WRITE` (`0x2`) — authority to mutate object state or write frame memory.
     - Bit 2: `GRANT` (`0x4`) — authority to transfer capabilities across synchronous IPC endpoints.
     - Bit 3: `GRANT_REPLY` (`0x8`) — authority to send and receive single-use reply capabilities without granting generic capability transfer.
     - Mask: `ALL = 0b1111` (`0xF`).
   - Bitwise algebraic operations: `contains`, `intersect`, `union`, `bitor`, `bitand`.
   - Strict validation: `from_bits` strictly rejects unknown bits above `0b1111`.

2. **Complete 18-Primitive seL4 Kernel Object Taxonomy (`KernelObjType` & `CapKind`)**:
   - `Untyped { size_bits: u8 }`: Raw physical memory allocator slab.
   - `Frame4K`, `Frame2M`, `Frame1G`: Physical addressable frames (4 KiB, 2 MiB, 1 GiB).
   - `Endpoint`: Synchronous rendezvous IPC channel (16 bytes).
   - `Notification`: Asynchronous event word / wait-signal channel (16 bytes).
   - `TCB`: Thread Control Block maintaining execution state and priority (1024 bytes).
   - `CNode { size_bits: u8 }`: Guarded radix capability table node (32 bytes per slot).
   - `SchedContext { budget_us, period_us }`: MCS execution budget context (64 bytes).
   - `Reply`: Single-use return capability generated on `seL4_Call` (32 bytes).
   - `PageTable`, `VSpace`: Hardware memory management structures (4096 bytes).
   - `ASIDPool`: Address Space Identifier pool allocator (4096 bytes).
   - `IrqControl`, `IrqHandler { irq: u8 }`: Interrupt routing tokens.
   - `IoPortControl`, `IoPort { start_port, end_port }`: x86 port I/O isolation tokens.
   - `IoSpace { pci_bdf, domain_id }`: Peripheral DMA containment tokens (IOMMU domains).
   - `Vcpu`: Hardware virtualization context (4096 bytes).

3. **Untyped Retyping & Memory Invariants**:
   - Retyping watermark allocation aligns to object size boundaries with minimum 16-byte alignment.
   - Device untyped invariant enforced: Device untyped memory (`is_device == true`) strictly rejects retyping into execution threads (`TCB`), endpoints, or capability tables (`CNode`), returning `SeL4Error::IllegalOperation`.
