## 1. Implementation Overview
In `kboot/src/lib.rs` and `kernel/src/arch/x86_64/mod.rs`:
1. **PE32+ UEFI Executable & Authenticode Parsing**:
   - Implemented structures: `PeDosHeader`, `PeCoffHeader`, `PeOptionalHeader64`, `PeSectionHeader`, `ImageDataDirectory`, `WinCertificate`.
   - Verified magic signatures: `PE_DOS_MAGIC` (`0x5A4D`), `PE_SIGNATURE` (`0x0000_4550`), `PE32PLUS_OPTIONAL_HEADER_MAGIC` (`0x020B`), machine type `IMAGE_FILE_MACHINE_AMD64` (`0x8664`).
   - Implemented `compute_authenticode_hash` according to Microsoft PE/COFF Authenticode specification (skipping 4-byte PE CheckSum, 8-byte Security Directory, and Attribute Certificate Table).
2. **Secure Boot Policy Enforcement**:
   - Added `SecureBootState` supporting `Disabled`, `Enabled`, `SetupMode`, `AuditMode`, and `DeployedMode`.
   - When Secure Boot is active (`Enabled` or `DeployedMode`), candidate images require a valid Authenticode Security Directory and supported signature type (`WIN_CERT_TYPE_PKCS_SIGNED_DATA`, `WIN_CERT_TYPE_EFI_PKCS115`, `WIN_CERT_TYPE_EFI_GUID`).
3. **TCG PC Client Measuring Loader (`MeasuringLoader`)**:
   - Implemented PCR extension: `PCR_new = SHA-256(PCR_old || measurement)`.
   - Measured candidate kernel binary into TPM 2.0 PCR 4 (`PCR_KERNEL_CODE`).
   - Appended measurement record into TCG Event Log (`TcgEventLogEntry` with event type `EV_IPL`).
   - Enforced anti-rollback monotonic epoch constraints (`verify_anti_rollback`), rejecting images with epoch < `KASH_SECURITY_EPOCH`.
4. **Bootloader Handoff & Status Registry**:
   - `MeasuringLoader::create_boot_info` constructs `KashBootInfo` with `boot_source = BootSource::Uefi`, GOP framebuffer, ACPI RSDP, and measured kernel hash.
   - `kernel/src/arch/x86_64/mod.rs` checks `boot_info.boot_source`: if `BootSource::Uefi`, updates `status.uefi_boot = ComponentStatus::Real` and `status.measured_boot = ComponentStatus::Real`. If booted via Multiboot/PVH, sets `status.bios_pvh_boot = ComponentStatus::Real`.
