# Evidence: Task A3 — Key Management Re-Audit

## Status

Needs revalidation. Audit date: 2026-10-20. The previous “Completed / Verified”
label was not supported by current source and has been removed. This revision
removes automatic unlock and adds an explicit hidden console unlock path; the
full persistent TPM hierarchy and GUI credential flow remain unfinished.

## Findings

- Before this revision, `kernel/src/kms.rs` defined
  `DEFAULT_BOOTSTRAP_PASSPHRASE` as a public fixed string and `init()` derived
  the active key without user input. Boot now starts locked; unlock requires
  a passphrase entered at a hidden console prompt.
- The KMS transform still uses a compiled-in salt and HKDF-SHA256. The
  encrypted volume then applies Argon2id using its own per-volume stored salt
  and parameters. A separate, versioned KMS password KDF and enrollment format
  are not implemented.
- `sealed_handle` starts at zero in memory and is not loaded from persistent
  TPM state. The apparent unseal-on-boot path therefore had no persistent
  provisioning source. The KMS no longer attempts this path or claims a TPM
  sealed key is active.
- The old source's public development credential was
  `KashOS-Sovereign-Node-2026`. Existing development volumes formatted with
  that credential remain accessible by entering it manually, but it is public
  and provides no meaningful secrecy. Do not use it for new data.

## Required work before A3 can be marked complete

Design and test user credential enrollment, a versioned password KDF with
documented parameters, persistent TPM object creation/recovery, hardware
failure behavior, lock/unlock lifecycle, and migration from legacy volumes.
Never silently reformat or make old encrypted data unrecoverable during this
change. The current credential path is console-only; a protected GUI flow is
still needed. The TPM driver's existing seal/unseal self-tests use an
in-memory model and do not verify TPM hardware commands.

## Verification

Source review was performed in `kernel/src/kms.rs`, `kernel/src/shell.rs`,
`kernel/src/session.rs`, and `kvault/src/crypto.rs` on 2026-10-20. Boot-locked
regression checks: 8 passed. Storage/network regression guards and the claims
linter pass. The workspace host suite passes (184 tests), the kernel target
check/release build pass, and QEMU reaches the console with KMS locked and T25
skipped without modifying the disk image. QEMU does not verify successful
interactive credential entry; no credential was sent to the user's disk.
