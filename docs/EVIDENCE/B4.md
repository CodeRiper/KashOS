# B4 evidence: badged endpoints and capability routing

## Current status

Needs revalidation. The `ksel4-core` milestone tests exercise a host-side model;
they do not establish that the kernel implements the same blocking, reply-cap,
or scheduling behavior.

The kernel supports direct message/capability delivery to an endpoint that
already has a staged waiter. Unmatched send and receive return
`SyscallError::WouldBlock` without mutating endpoint or process state. The
kernel does not yet suspend and resume a syscall around a rendezvous; therefore
B4 synchronous blocking and `seL4_Call` parity are not implemented.

See [`B4-ipc-would-block.md`](B4-ipc-would-block.md) for the source audit,
correction, regression guard, and verification. See
[`../design/b4-ipc-blocking.md`](../design/b4-ipc-blocking.md) for the
remaining implementation requirements.

## Host model tests

`ksel4-core/tests/milestones.rs::test_sel4_badged_synchronous_endpoints_and_capability_routing`
checks the standalone `ksel4-core` model's non-blocking, badging, rights,
capability-routing, and reply protocol behavior. These tests do not run through
`kernel/src/ipc.rs`, the x86 syscall entry path, or the kernel scheduler. Treat
them as model tests only.
