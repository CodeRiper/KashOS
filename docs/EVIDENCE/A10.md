# Evidence: Task A10 — User-Space Services and Ring 3 Transition

## Status

Needs revalidation; the planned service migration is incomplete. Audit date:
2026-10-20.

## Finding

Ring 3 entry, syscall, and fault-handling mechanisms are exercised by boot
self-tests using hand-built test programs. The normal boot path does not spawn
the desktop, settings UI, or console as user processes. `session.rs` invokes the
desktop and shell directly while still in Ring 0. The old A10 evidence marked
this task complete because it moved calls from `main.rs` into a module and
treated synthetic capabilities as a user session; that conclusion was wrong.

The process launcher and user-mode mechanisms do not demonstrate that the
ordinary services run in Ring 3. `UserSession::setup_capabilities` previously installed
fabricated addresses and broad model capabilities without creating a process;
that setup has been removed. The `run-user` shell command now reports the
missing boot integration rather than printing a successful transition.

## Changes in this revalidation

- Renamed the boot handoff to `launch_kernel_resident_session` and made its
  logs state that the desktop and console remain in Ring 0.
- Removed the fake session CSpace setup and associated claim that a user
  session had been spawned.
- Changed the Ring 3 status from Real to Partial after T13, since T13 exercises
  a test process while normal user services are not connected.
- Corrected the settings/status output, README, claims table, and master-plan
  finding. Updated the ground-truth verifier to inspect the actual session
  call sites instead of only searching `main.rs`.
- Added a CI regression guard for the kernel-resident session and its status
  labels.

## Verification

The fail-closed claim guard verifies that the ordinary desktop and console are
identified as kernel-resident, fake session capabilities are absent, the
status remains Partial, and the verifier detects the current F10 condition.
Build and boot tests check that this honesty correction preserves the existing
prototype UI boot path. Those tests do not establish process isolation for the
desktop, shell, settings, browser, file service, or device drivers.

## Remaining work

A10 remains open. It requires a real user-space init/session manager, verified
physical page and stack allocation, process address spaces mapped from user
ELF images, syscall/IPC authority tied to per-process capabilities, fault and
restart containment, and migration of the desktop and shell out of Ring 0.
Until those pieces are implemented and integration-tested, the system is a
Ring-0 UI prototype with separately tested Ring 3 mechanisms.
